在一段三地址码 IR 上实现三个经典优化。IR 是一个指令列表，每条指令是元组 `(dst, op, args)`：

- `("t1", "const", (2.0,))`：常量；
- `("t3", "+", ("t1", "t2"))`：二元运算，`op` 是 `"+"`、`"-"`、`"*"` 之一；
- `("out", "store", ("t9",))`：把某个值写到输出（一段 IR 里可以有多条 store，`dst` 是输出名）。

实现：

1. `const_fold(instrs)`：两个操作数都是常量的运算直接算出来，变成 `const` 指令；
2. `cse(instrs)`：公共子表达式消除——同样的 `(op, 参数)` 只算一次，后面的引用改名；
3. `dce(instrs)`：死代码消除——删掉结果没被任何 store 直接或间接用到的指令；
4. `optimize(instrs)`：按"折叠 → CSE → DCE"跑一遍，返回优化后的 IR。

```python
ir = [("a", "const", (2.0,)), ("t1", "+", ("x", "a")), ("t2", "+", ("x", "a")),
      ("t3", "*", ("t1", "t2")), ("t4", "*", ("x", "x")), ("out", "store", ("t3",))]
[i[0] for i in optimize(ir)]        # ['a', 't1', 't3', 'out']：t2 被合并、t4 没人用
```

<!-- 题解 -->
三个 pass 的共同点是"一次线性扫描 + 一张表"：

- **常量折叠**：维护 `值名 -> 常量`，两个操作数都在表里就直接算；
- **CSE**：维护 `(op, 参数) -> 第一次算出它的变量名`，重复的表达式不再生成指令，只在 `rename` 表里记下"以后见到 t4 就用 t3"。后续指令的参数都要先过一遍 `rename`；
- **DCE**：从所有 store 的参数出发反向传播"活跃"集合，不活跃的指令删掉。必须**倒着**遍历，否则后面指令用到的名字还没被标记。

顺序很重要：先折叠让更多表达式变成常量、先 CSE 让重复计算的结果统一，最后 DCE 才能删得干净。真实编译器里这些 pass 会反复跑到不动点。

注意浮点运算不满足结合律，所以**不能**把 `(a + b) + c` 重排成 `a + (b + c)`——这正是确定性推理要小心的地方（见[确定性推理](serving://topics/deterministic/)）。
