GEMM 的主循环要处理 `K` 个分块，每块都要"从全局内存拷到共享内存（耗时 `L`）"然后"计算（耗时 `C`）"。
用 `cp.async` 做 **S 级流水线**：共享内存里有 `S` 个缓冲区，拷贝和计算可以重叠。按下面的规则模拟一个 warp 的执行，计算总耗时：

- 拷贝引擎是异步的：发出拷贝请求不花时间，拷贝在后台执行，**同一时刻只能有一个拷贝在进行**（带宽有限，拷贝按发出的顺序排队，一个完成后下一个才开始）；
- 计算单元同一时刻只做一块，计算第 `k` 块必须等第 `k` 块拷完；
- 缓冲区：第 `k` 块用缓冲区 `k % S`。第 `k` 块的拷贝必须等到**同一个缓冲区上一次使用的那块**（第 `k - S` 块）**计算完成**之后才能开始；
- 开始时（时间 0）立即发出前 `min(S, K)` 块的拷贝请求；之后每当第 `j` 块计算完成，就发出第 `j + S` 块（如果存在）的拷贝请求。

实现 `pipeline_time(K, L, C, S)` 返回全部计算完成的时间，以及 `schedule(K, L, C, S)` 返回每块的 `(拷贝开始, 拷贝结束, 计算开始, 计算结束)` 列表。

```python
pipeline_time(4, 10, 10, 1)    # 80：没有重叠，(10 + 10) × 4
pipeline_time(4, 10, 10, 2)    # 50：拷贝和计算重叠
pipeline_time(8, 4, 10, 3)     # 84：计算是瓶颈，4 + 8 × 10
```

<!-- 题解 -->
按块的编号顺序模拟即可（拷贝按编号排队，计算也按编号进行）：

```text
copy_start[k]  = max(上一个拷贝结束, 请求时间[k])        请求时间：k < S 时为 0，否则是 compute_end[k - S]
copy_end[k]    = copy_start[k] + L
compute_start[k] = max(copy_end[k], compute_end[k - 1])
compute_end[k]   = compute_start[k] + C
```

`S = 1` 时拷贝和计算完全串行；`S` 足够大时总时间趋近 $L + K \cdot \max(L, C) + \ldots$，瓶颈是拷贝和计算里慢的那个。
Hopper 的 TMA + warp 专门化把"发拷贝"和"做计算"交给不同的 warp，思路相同。
