`pyproject.toml` 里常写 `torch>=2.4,<3`、`numpy~=1.26`。实现一个简化版的版本约束检查：

**`parse_version(s)`**：把 `"2.4.1"`、`"2.4"`、`"12.8.0rc1"` 解析成可以直接比较的元组。规则：

- 版本号是若干段非负整数，用 `.` 分隔；比较时**末尾补 0**：`2.4 == 2.4.0`；
- 可以带预发布后缀 `a`、`b`、`rc` 加数字（例如 `2.5.0rc1`），预发布版本**小于**对应的正式版：`2.5.0a1 < 2.5.0b2 < 2.5.0rc1 < 2.5.0`；
- 格式不对抛出 `ValueError`。

**`satisfies(version, spec)`**：`spec` 是逗号分隔的若干个约束，全部满足才返回 `True`。支持的运算符：

| 运算符 | 含义 |
| --- | --- |
| `==X` | 等于（`==2.4` 和 `2.4.0` 相等） |
| `!=X` | 不等于 |
| `>=X`、`>X`、`<=X`、`<X` | 比较 |
| `~=X` | 兼容版本：`~=1.26` 等价于 `>=1.26,<2`；`~=1.26.2` 等价于 `>=1.26.2,<1.27`（至少两段） |

约束两边可以有空格；空字符串表示没有约束。

```python
satisfies("2.4.1", ">=2.4, <3")     # True
satisfies("1.27.0", "~=1.26.2")     # False
satisfies("2.5.0rc1", ">=2.5")      # False，预发布版小于 2.5
```

<!-- 题解 -->
把版本变成 `(数字段元组, 预发布键)`：数字段先去掉末尾的 0（这样 `2.4` 和 `2.4.0` 的元组相同），
预发布键用 `(0, 数字)`、`(1, 数字)`、`(2, 数字)` 表示 a、b、rc，正式版用 `(3, 0)`，这样元组比较的结果就是版本比较的结果。

`~=X`：设 `X` 有 $k$ 段，上界是"去掉最后一段、把倒数第二段加 1"。
