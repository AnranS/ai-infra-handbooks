这道题反过来：**实现已经给定，你来写测试**。

被测函数 `parse_size(s)` 把表示大小的字符串解析成字节数（`int`）：

- 纯数字表示字节：`"512"` → `512`；
- 单位（大小写不敏感）：`B`；十进制 `KB`、`MB`、`GB`（1000 的幂）；二进制 `KiB`、`MiB`、`GiB`（1024 的幂）；
- 数字和单位之间可以有空格，数字可以是小数：`"1.5 KiB"` → `1536`；
- 结果必须是整数字节，否则抛出 `ValueError`（`"0.5B"`）；负数、空字符串、未知单位也抛出 `ValueError`。

写若干个测试函数，名字以 `test_` 开头，**每个函数接收一个参数 `parse_size`**（判题时会传入不同的实现）：

```python
def test_binary_units(parse_size):
    assert parse_size("2KiB") == 2048
```

判题规则：

1. 至少写 3 个测试；
2. 用**正确的实现**运行时，你的所有测试都要通过；
3. 判题器准备了 6 个**有 bug 的实现**（变异体），每一个都要被你至少一个测试抓住（断言失败或抛出异常）。

测试"是否抛出 ValueError"时，可以用 `try/except`，或者从 `checker` 里导入 `raises`：`with raises(ValueError): parse_size("-1")`。

<!-- 题解 -->
6 个变异体分别是：把 `KiB` 当成 1000、单位大小写敏感、不允许数字和单位之间有空格、接受负数、先把小数截断成整数再乘、把 `GB` 当成 1024³。
好的测试要覆盖每一类输入：纯数字、每种单位（十进制和二进制都要有）、大小写、空格、小数、各种非法输入。
变异测试（mutation testing）就是用这种方式衡量测试的质量：测试抓不住的变异体，说明那部分行为没被测到。
