---
一批请求按到达顺序排好，每个请求是一串 token id。对第 `i` 个请求，求它和**前面任意一个请求**的最长公共前缀长度（前缀缓存能复用的 token 数）；第一个请求的答案是 0。

```python
prefix_hits([[1, 2, 3], [1, 2, 4], [1, 2, 3, 5], [7]])   # [0, 2, 3, 0]
```

模板里是直接两两比较的写法，结果正确但太慢：请求数到几千、每个几百 token 时要跑几十秒。
请优化到**总 token 数的线性复杂度**：2000 个请求、每个约 300 个 token，要在 1 秒内完成（浏览器里放宽到 3 秒）。

<!-- 题解 -->
用字典树（trie）：每个节点是一个 `dict`，从 token 映射到子节点。处理第 `i` 个请求时，先沿着字典树往下走，
能走多深就是答案；然后把这个请求插入字典树（沿着同一条路径继续往下建节点）。每个 token 只访问一次，总复杂度 $O(\sum L_i)$。

这正是 SGLang 的 Radix Cache 的核心思想（再把没有分叉的链压缩成一个节点就是基数树）。
