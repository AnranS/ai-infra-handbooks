OpenAI 接口的 `stop` 参数是**字符串**，不是 token：`stop=["\nUser:", "###"]`。流式输出时，文本是一小段一小段增量产生的，停止字符串可能跨越好几段。
如果把每段文本立刻发给客户端，等发现 `"\nUs"` 后面跟着 `"er:"` 时，前半截已经发出去了。

实现 `StopChecker(stops, include_stop=False)`：

- `feed(delta) -> (emit, finished)`：输入新产生的一段文本。返回这次**可以安全发给客户端**的文本，以及是否遇到了停止字符串；
  - 一旦出现某个停止字符串：返回它**之前**的所有未发送文本（`include_stop=True` 时连同停止字符串本身），`finished=True`；之后再调用 `feed` 返回 `("", True)`；
  - 没有出现时：末尾可能是某个停止字符串的**前缀**的那部分要先扣住不发（它也许会和下一段拼成停止字符串），其余的发出去；
  - 多个停止字符串都出现时，以**最早出现的位置**为准（位置相同时取更长的那个）；
- `flush() -> str`：生成结束（例如达到 `max_tokens`）时调用，返回被扣住的文本；已经 `finished` 时返回 `""`。

要求：不论文本被怎样切分，所有 `emit` 拼起来（加上最后的 `flush`）都等于"对完整文本做一次性截断"的结果；并且每个时刻扣住的文本长度不超过 `max(len(s) for s in stops) - 1`。

<!-- 题解 -->
维护一个缓冲区 `buf`（已收到、未发送的文本）：

1. `buf += delta`，在 `buf` 里找每个停止字符串的最早位置，取最小的；找到就返回 `buf[:pos]`（或 `buf[:pos + len(s)]`）并标记结束；
2. 否则，求 `buf` 的最长后缀，使它是某个停止字符串的前缀（长度最多 `max_len - 1`）；发出 `buf[:-k]`，留下后缀。

因为每次都在"新旧拼接后的 buf"里搜索，跨段的停止字符串一定会被找到；而被发出去的部分不可能是任何停止字符串的开头（否则它会被扣住）。
vLLM、SGLang 的 detokenizer 里都有这段逻辑，还要额外处理"停止字符串跨越 token 边界、并且和不完整的 UTF-8 字节混在一起"的情况。
