DeepSeek-V3 式的 FP8 推理：激活每个 token 每 128 个通道一个缩放，权重每个 128×128 的块一个缩放，GEMM 沿 K 维每 128 个元素做一次 FP8 矩阵乘、在 fp32 里乘上两个缩放后累加。这道题不用 PyTorch 的 `float8_e4m3fn`，自己实现 E4M3 的舍入。

E4M3（`fn` 变体，没有 inf）：1 位符号、4 位指数（偏置 7）、3 位尾数。规格化数是 $(1 + m/8) \cdot 2^{e}$，$e \in [-6, 8]$；非规格化数是 $m \cdot 2^{-9}$（$m = 1..7$）；最大值 448。

1. `e4m3(x)`：把数组 `x` 的每个元素舍入到最近的 E4M3 值（正好在两个值中间时取尾数为偶数的那个），绝对值超过 448 的饱和到 ±448；返回 `float32` 数组；
2. `quant_act(a, group=128, pow2=False)`：`a` 的形状是 `(M, K)`。每行每 `group` 个元素一组，缩放 `s = amax / 448`（整组都是 0 时 `s = 1`）；`pow2=True` 时把缩放向上取到 2 的幂（Blackwell 的 MXFP8、DeepSeek-V3.1 之后用的 UE8M0 缩放）。返回 `(q, s)`：`q = e4m3(a / s)`，形状 `(M, K)`；`s` 的形状 `(M, K // group)`；
3. `quant_weight(w, block=128, pow2=False)`：`w` 的形状是 `(K, N)`，每个 `block × block` 的块一个缩放，返回 `(q, s)`，`s` 的形状 `(K // block, N // block)`；
4. `block_gemm(aq, sa, wq, sw)`：按上面的算法算 `(M, N)` 的输出（fp32）。组的大小从形状推出来：`K // sa.shape[1]`。

```python
e4m3(np.array([1.0, 1.0625, 0.3, 500.0, 2**-10, 3 * 2**-10]))
# [1.0, 1.0, 0.3125, 448.0, 0.0, 0.00390625]
```

<!-- 题解 -->
舍入的关键是先找到 $x$ 所在的"二进制区间"：指数 $e = \lfloor \log_2 |x| \rfloor$，夹在 $[-6, 8]$ 里（低于 $-6$ 的都按非规格化数的步长 $2^{-9}$ 处理），这个区间里相邻两个值的间隔是 $2^{e-3}$，`np.rint(|x| / 间隔) * 间隔` 就是向最近的偶数舍入。舍入可能进位到下一个区间（1.97 → 2.0），这正好也是一个合法的值；最后与 448 取较小值实现饱和。

分块缩放的意义在离群值：一个大值只影响它所在的那 128 个通道，其他组的缩放不变；整行一个缩放时，正常的数被压进非规格化数甚至 0。测试里的最后一个用例就是这个实验。
2 的幂的缩放让"乘缩放"变成只改指数，硬件更便宜；代价是缩放最多偏大一倍，相当于浪费了不到 1 位的动态范围。
