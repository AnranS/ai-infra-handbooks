分布式 KV 存储用**前缀链式哈希**作为块的全局键：第 `i` 块的键是 `hash((第 i-1 块的键, 第 i 块的 token 元组))`，第 0 块的"前一个键"是 `seed`（可以用来区分模型版本、LoRA、租户）。只有完整的块才有键。

实现：

1. `block_keys(tokens, block, seed=0)`：返回每个完整块的键（Python 内置的 `hash`，参数就是上面的二元组）；
2. `longest_hit(keys, tiers)`：`tiers` 是按从快到慢排列的若干个集合（例如 `[本卡, 本机内存, 远端 KV 池]`）。从第 0 块开始往后找，每一块只要在**任意一层**里就算命中，遇到第一个不命中的块就停止（KV 依赖整个前缀，后面的块即使存在也用不了）。返回一个列表，第 `i` 项是第 `i` 个命中块所在的**最快**那一层的下标；
3. `plan_load(keys, tiers, block, cost_per_tier, recompute_cost)`：对命中的前缀，逐块比较"从所在层读回"与"重新计算"的代价（`cost_per_tier[t]` 和 `recompute_cost` 都是每个 token 的代价），返回 `(读回的 token 数, 需要计算的 token 数)`。为了简单，**只有读回比重算便宜的块**才读回；一旦某块选择重算，它后面的块也必须重算（前缀依赖），未命中的部分当然要算。token 总数按 `len(keys) * block` 计。

```python
keys = block_keys(list(range(40)), 16)                 # 两个完整的块
longest_hit(keys, [set(), {keys[0]}, {keys[1]}])       # [1, 2]
```

<!-- 题解 -->
链式哈希让一个块的键代表"从开头到这一块的整个前缀"：前缀中任何一个 token 不同，此后所有块的键都不同。这正好符合 KV 的语义，也让不同实例、不同存储层能用同一个键认出同一段 KV，而不需要比较 token 序列。
`plan_load` 体现了"读回来要比重算快才划算"：远端或 SSD 上的块，如果读取代价超过重算（短前缀、小模型、带宽紧张时），就应该放弃；而且放弃之后，后面的块即使命中也只能重算。真实系统还会把读取和计算重叠（逐层加载），代价的比较会更细。
