专家并行里，每张卡放着若干个物理专家（同一个逻辑专家可能有多个副本，放在不同的卡上）。某些卡坏了之后，如果一个逻辑专家的所有副本都在坏卡上，它就"丢了"，只能从内存备份或磁盘补回来。`cards` 是一个列表，第 g 项是第 g 张卡上的逻辑专家编号列表。实现：

1. `lost_experts(cards, dead)`：`dead` 是坏卡编号的集合，返回丢了的逻辑专家（升序列表）。只统计至少在一张卡上出现过的专家；
2. `min_failures_to_lose(cards)`：最少坏几张卡就可能丢专家（等于"副本所在的不同卡数"最少的那个专家的卡数）；
3. `prob_no_loss(cards, k)`：从所有卡里等可能地挑 k 张坏掉（不放回），一个专家都不丢的概率。要求精确计算（返回 `fractions.Fraction`），卡数不超过 20；
4. `replica_counts(num_experts, load, extra)`：给最热的专家加副本：每个专家先放 1 份，再把 `extra` 份额外的副本逐个分给"当前每份副本平均负载"（`load[e] / 副本数`）最大的专家（相等时编号小的优先），返回每个专家的副本数列表。

```python
cards = [[0, 1], [2, 3], [0, 2], [1, 3]]
lost_experts(cards, {0, 2})          # [0]：专家 0 的两份都在坏卡上
min_failures_to_lose(cards)          # 2
prob_no_loss(cards, 2)               # Fraction(1, 3)
```

<!-- 题解 -->
`lost_experts` 就是"所有专家"减去"活着的卡上出现过的专家"。`min_failures_to_lose` 看的是每个专家分布在几张不同的卡上：只有一份的专家，坏一张卡就可能丢；每个专家都有两份（分在不同的卡上），至少坏两张才可能丢。

`prob_no_loss` 枚举所有 k 张卡的组合，数一数有几种不丢专家，除以组合总数 C(n, k)。例子里坏两张卡一共 6 种组合，只有 {0, 3} 和 {1, 2} 两种不丢，概率 1/3——即使每个专家都有两份，坏两张卡也有 2/3 的概率丢专家，这正是正文估算的结论：冗余副本的主要作用是负载均衡，兜底要靠备份。

`replica_counts` 是 EPLB 复制热门专家的贪心：每次把一份额外的副本给"平均每份最忙"的专家，这样加完之后各份副本的负载尽量平均。热门专家拿到的副本多，但大部分专家仍只有一份——所以坏一张卡几乎一定丢专家。
