实现一个 O(1) 的 LFU（最不常用）缓存 `LFUCache(capacity)`：

- `get(key)`：存在则返回值并让它的使用次数加一，否则返回 -1；
- `put(key, value)`：写入或更新（更新也算一次使用）；超容时淘汰**使用次数最少**的键，次数相同时淘汰**最久未使用**的；
- `keys_by_freq()`：返回 `[(key, 使用次数), ...]`，按次数升序、同次数按最久未使用在前（用于测试）。

```python
c = LFUCache(2)
c.put(1, 1); c.put(2, 2)
c.get(1)            # 1，键 1 的次数变成 2
c.put(3, 3)         # 淘汰次数最少的键 2
c.get(2)            # -1
```

<!-- 题解 -->
LFU 要同时按"次数"和"同次数内的时间顺序"排序，所以用三个结构：`key -> (值, 次数)`、`次数 -> 该次数下的键（有序字典，保持插入顺序）`、以及一个 `min_freq` 记录当前最小次数。

- `get`/`put` 命中：把键从 `freq` 桶里移到 `freq+1` 桶的末尾；如果原来的桶空了且它正好是 `min_freq`，就把 `min_freq` 加一；
- 插入新键：次数为 1，`min_freq` 重置为 1；
- 淘汰：从 `min_freq` 桶的**最前面**取（最久未使用）。

所有操作都是 O(1)。容易错的地方：更新已有键时要算作一次使用；`min_freq` 的维护（桶空了才加一）；容量为 0 时什么都存不下。

LFU 对"长期热点"比 LRU 更准，但对突发流量反应慢（一个刚进来的键次数是 1，很容易被淘汰），所以实践中常用带衰减的变体（TinyLFU、窗口 LFU）。推理引擎的块池默认用 LRU，正是因为请求的局部性比长期频率更重要。
