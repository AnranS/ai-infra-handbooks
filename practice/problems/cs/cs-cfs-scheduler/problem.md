实现一个简化的 CFS 调度器 `simulate(tasks, total_ms)`。`tasks` 是 `[(name, nice, arrive_ms), ...]`，时间从 0 开始，每 1 毫秒调度一次，模拟到 `total_ms` 为止：

1. 时刻 `t` 可运行的任务是已经到达的任务（`arrive_ms <= t`）；从中选**虚拟运行时间最小**的运行 1 毫秒，一样小时按 `name` 的字典序选第一个；
2. 运行之后，它的虚拟运行时间增加 `1024 / WEIGHT[nice]`（权重表 `WEIGHT` 已经在模板里给出，取自内核的 `sched_prio_to_weight`）；
3. 任务在时刻 `t` 到达时，虚拟运行时间初始化为**此刻其他可运行任务的最小虚拟运行时间**；没有其他可运行任务时为 0。否则一个晚到的任务会从 0 开始，长时间独占 CPU；
4. 某一毫秒没有可运行的任务，CPU 就空闲。

返回字典：每个任务名 → 实际运行了多少毫秒。

```python
simulate([("a", 0, 0), ("b", 5, 0)], 1000)     # {"a": 753, "b": 247}，按权重 1024 : 335 分配
simulate([("a", 0, 0), ("b", 0, 500)], 1000)   # {"a": 750, "b": 250}：b 晚到，只和 a 平分后面的 500 ms
```

<!-- 题解 -->
CFS 的核心是"总是运行虚拟运行时间最小的任务"：运行时间按权重折算成虚拟时间，权重大的任务虚拟时间走得慢，被选中的次数就多，长期来看每个任务的 CPU 时间和权重成正比。内核用红黑树按虚拟运行时间排序、取最左边的节点，这里任务很少，每次线性扫描就够了。

晚到任务的处理是这道题的关键。它如果从 0 开始，而别的任务已经累积了很大的虚拟运行时间，就会连续运行很久、把其他任务饿住。内核在任务加入运行队列时（`place_entity`）把它的虚拟运行时间放到当前最小值附近，这里简化成"等于其他可运行任务的最小值"。睡眠后被唤醒的任务也是同样的处理，所以一个睡了很久的任务醒来后，不会因为"欠了很多 CPU"而独占处理器。
