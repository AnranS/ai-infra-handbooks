给一个有向图（`n` 个节点编号 `0..n-1`，`edges` 是 `[(a, b), ...]` 表示 `a` 必须在 `b` 之前），实现：

1. `topo_order(n, edges)`：返回一个合法的执行顺序；有环返回 `None`。同时可选的节点**按编号从小到大**出队，保证结果唯一；
2. `longest_path(n, edges)`：每个节点耗时 1，返回"全部完成最少需要几层"（即最长路径上的节点数）；有环返回 -1。

```python
topo_order(4, [(0, 1), (0, 2), (1, 3), (2, 3)])    # [0, 1, 2, 3]
topo_order(2, [(0, 1), (1, 0)])                    # None
longest_path(4, [(0, 1), (0, 2), (1, 3), (2, 3)])  # 3
```

<!-- 题解 -->
Kahn 算法：统计每个节点的入度，把入度为 0 的放进队列；每次出队一个节点，把它所有后继的入度减一，减到 0 就入队。**出队的节点数少于 n，说明剩下的节点在环里**。用最小堆代替普通队列，就能得到字典序最小的拓扑序。

`longest_path` 在拓扑序上做一次动态规划：`level[b] = max(level[b], level[a] + 1)`。它就是计算图的"关键路径"——一个算子要等所有前驱完成，所以是最长路而不是最短路。层数也等于"理想情况下（资源无限）需要多少轮"。

对应的工程场景：计算图的执行顺序与流水线深度、任务依赖调度、模型并行里各段的先后关系。如果图里出现环，说明依赖定义有误——这也是框架在构图阶段必须检查的。
