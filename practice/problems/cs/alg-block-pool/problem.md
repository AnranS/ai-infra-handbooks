实现一个简化版的 KV 块池——这正是推理引擎里分页 KV Cache 的核心结构：

`BlockPool(num_blocks)` 管理编号 `0 .. num_blocks-1` 的块。

- `allocate(block_hash)`：申请一个块。`block_hash` 非 `None` 且**已经在缓存里**时，直接复用那个块（引用计数加一）并返回它的编号；否则取一个空闲块（优先取**最久未使用**的，即先释放的先复用），登记它的哈希（`None` 表示不可复用），返回编号。没有空闲块时返回 -1；
- `free(block_id)`：引用计数减一；减到 0 时放回空闲队列的**队尾**（不清除哈希，等被真正复用时才失效）；
- `num_free()`：当前空闲块数；
- `hit_rate()`：`allocate` 的缓存命中率（命中次数 ÷ 调用次数），没有调用过返回 0.0。

```python
p = BlockPool(2)
a = p.allocate("h1")        # 0
b = p.allocate("h1")        # 0：命中缓存，引用计数变 2
p.free(a); p.free(b)        # 计数归零，块 0 回到空闲队列（此时 num_free() == 2）
p.allocate("h1")            # 0：仍然命中
round(p.hit_rate(), 2)      # 0.67
```

<!-- 题解 -->
三个结构配合：`哈希 -> 块号` 的字典（缓存查找）、`块号 -> 引用计数`、以及空闲块的**双端队列**（先释放的先复用，就是 LRU）。

三个容易错的地方：（1）命中缓存的块如果引用计数为 0，它还躺在空闲队列里，复用时要把它从队列里摘掉；（2）复用一个有旧哈希的空闲块时，要把旧哈希从缓存字典里删掉，否则会返回一个内容已经不对的块；（3）引用计数减到 0 才放回队列，正在被使用的块不能被别人抢走。

真实系统还要多两层：块哈希要包含**父块的哈希**（保证前缀完全一致才复用）；淘汰要考虑正在被使用的请求（引用计数就是干这个的）。vLLM 的 `BlockPool` 把没有哈希的块放队头（LIFO，利于 GPU 局部性）、有哈希的放队尾（LRU）；SGLang 用带引用计数的基数树。见[前缀缓存](serving://engine/prefix-cache/)。
