三个经典的区间问题（区间都是 `[start, end]` 闭区间）：

1. `merge(intervals)`：合并所有重叠区间，返回按起点升序的结果（相邻但不重叠的不合并，比如 `[1,2]` 和 `[3,4]`）；
2. `min_remove(intervals)`：最少删掉几个区间，才能让剩下的互不重叠（端点相接不算重叠）；
3. `max_concurrent(intervals)`：任意时刻最多有几个区间同时存在（一个区间在 `end` 时刻已经结束，不与从 `end` 开始的区间重叠）。

```python
merge([[1, 3], [2, 6], [8, 10]])              # [[1, 6], [8, 10]]
min_remove([[1, 2], [2, 3], [3, 4], [1, 3]])  # 1
max_concurrent([[1, 4], [2, 5], [5, 6]])      # 2
```

<!-- 题解 -->
三题排序的关键字不同，这是最容易记混的地方：

- **合并**按**起点**排序：能接上（`start <= 当前右端点`）就扩展右端点，否则新开一个区间；
- **最少删除**按**终点**排序：能留就留（`start >= 上一个保留的终点`）。为什么按终点？交换论证：在所有能选的区间里，选终点最早的那个，给后面留下的空间最大，不会比任何其他选择更差。按起点排序是错的——先开始的区间可能很长，挡住后面好几个短的；
- **最大并发**把端点拆开排序：`+1` 表示开始、`-1` 表示结束，同一时刻**先处理结束**。这就是差分数组的思想，也是"需要几个会议室""需要几个并发槽位"的标准解法。

推理系统里的对应：并发槽位的峰值决定了 KV 显存的上限；请求的生命周期区间用同一套方法统计。
