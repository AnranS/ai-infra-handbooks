asyncio 的事件循环是单线程的：协程在 `await` 处让出，事件循环去等 I/O 或定时器，再把就绪的协程接着往下跑。用生成器模拟一个带虚拟时钟的事件循环 `run(tasks)`。`tasks` 是字典 `名字 → 生成器`，生成器会产出两种请求：

- `("sleep", s)`：非阻塞地等 `s` 秒（相当于 `await asyncio.sleep(s)`），期间别的任务可以运行；
- `("cpu", s)`：在协程里做了 `s` 秒的同步计算（相当于在协程里调用了阻塞函数），时钟直接前进 `s`，这段时间谁也跑不了；做完之后这个任务排到就绪队列的末尾。

规则：时钟从 0 开始；一开始按字典的顺序把所有任务放进就绪队列（先进先出）。每一轮先把所有已经到期（到期时刻 ≤ 当前时钟）的定时器按到期时间、再按登记的先后放到就绪队列末尾；如果就绪队列还是空的，就把时钟拨到最早的定时器，再这样放一次。然后从就绪队列头部取一个任务，让它运行到下一个请求为止（第一次用 `next(gen)`，之后用 `gen.send(None)`）；生成器结束（`StopIteration`）时记录它的完成时刻。时钟只会前进，不会倒退。返回字典：名字 → 完成时刻（保留 6 位小数）。

```python
def sleeper():
    yield ("sleep", 0.1)

def blocker():
    yield ("cpu", 0.3)

run({"a": sleeper(), "b": sleeper()})                  # {"a": 0.1, "b": 0.1}：两个等待是重叠的
run({"bad": blocker(), "a": sleeper(), "b": sleeper()})  # {"bad": 0.3, "a": 0.4, "b": 0.4}
```

<!-- 题解 -->
事件循环 = 就绪队列 + 定时器堆 + 一个"没事做就等到下一个事件"的循环。`("sleep", s)` 只是登记一个"s 秒后叫醒我"的定时器，让出之后事件循环立刻去跑别的任务，所以一千个各等 0.1 秒的任务总共也只要 0.1 秒。`("cpu", s)` 则不同：事件循环只有一个线程，这个任务不让出，时钟就被它独占着往前走——第二个例子里 `a`、`b` 本来 0.1 秒就能完成，却要等 `bad` 算完 0.3 秒才开始睡，于是 0.4 秒才完成。

这就是"不要在协程里做阻塞调用"的由来：推理服务的事件循环里一次 30 ms 的同步分词，会让所有正在流式输出的连接一起停顿 30 ms。定时器用 `heapq`，堆里放 `(到期时间, 登记序号, 名字)`，序号保证同一时刻到期的任务按登记顺序出堆。还有一个容易写错的地方：同步计算会让时钟越过一些定时器的到期时刻，这些任务要在下一轮就放回就绪队列，而不是等就绪队列空了再把时钟"拨回"到它们的到期时刻——asyncio 的 `_run_once` 也是每一轮先处理到期的定时器，再运行就绪的回调。
