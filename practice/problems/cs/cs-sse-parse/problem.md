流式接口的响应体是"分块传输编码 + SSE 事件"。实现两个函数，它们都要能处理**按任意边界切开**的数据（网络上每次 `recv` 收到多少是不确定的）：

1. `dechunk(stream)`：`stream` 是若干 `bytes` 片段的可迭代对象，拼起来是完整的分块传输编码体。逐块解码，返回解码后的完整 `bytes`。每块的格式是 `十六进制长度\r\n数据\r\n`，长度为 0 的块表示结束（结束块之后的数据忽略）；
2. `sse_events(body)`：把 SSE 正文（`bytes`）解析成事件列表。事件之间用空行分隔，每行形如 `字段: 值`（冒号后的一个空格可选）。只需要处理 `data` 和 `event` 两个字段：同一事件里多行 `data` 用 `\n` 连接；返回 `[(event 或 None, data), ...]`，`data` 为空的事件跳过；以冒号开头的注释行（心跳）忽略。

```python
dechunk([b"5\r\nhel", b"lo\r\n3\r\nabc\r\n0\r\n\r\n"])        # b"helloabc"
sse_events(b"data: a\ndata: b\n\nevent: done\ndata: [DONE]\n\n")
# [(None, "a\nb"), ("done", "[DONE]")]
```

<!-- 题解 -->
两个函数的共同点是**不能假设数据的切分边界**：收到的片段可能在长度行中间、也可能在数据中间断开。写法是维护一个缓冲区，能解析出一个完整单元就解析，不够就继续读。这类"增量解析"是所有协议代码的基本功。

`dechunk`：先找 `\r\n` 拿到十六进制长度，再等够 `长度 + 2` 个字节（数据加结尾的 `\r\n`）。长度为 0 就结束。真实的实现还要处理块扩展（长度后面的 `;参数`）和结尾的 trailer 头。

`sse_events`：按空行切事件，事件内按行取字段。`data:` 后面的一个空格是格式的一部分要去掉，但只去一个（`data:  x` 的值是 ` x`）。注释行（以 `:` 开头）用来当心跳，穿过那些"长时间没数据就断开"的中间设备。
