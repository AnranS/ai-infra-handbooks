推理系统岗 17 周冲刺计划

目标是头部大模型公司的推理系统 / AI Infra 岗位。四个阶段：先把 C++、CUDA、大模型和推理引擎的基础打牢，再深入框架源码和分布式推理，然后吃透前沿推理系统并做出有辨识度的作品，最后集中准备面试。每一周都对应到手册的章节、练习题和可检验的产出。

目标能力学习目标与验证三类岗位差异化路线 逐周计划里程碑作品与开源参考教程 面试准备每周节奏配套内容建设

目标：面试官眼里的“能进来”

推理系统岗的面试通常围绕六块能力展开。每块写的是“达标”时应该能做到的事——不是“看过”，而是能在白板上写出来、能用数字讲清楚、能回答追问。

学习目标分四级，每一级都能验证

“学过”不算数。每个知识点的目标写成四级之一：讲清、写对、做快、交付；逐周验收清单的每一项都标了等级，并对应到下面的验证方式。越往后的阶段，L3、L4 的比例越高。

模拟面试评分：正确性（有没有错）、深度（能接住几层追问）、数字（能否给出量级与估算）、沟通（先结论后细节、结构清楚），每项 1～4 分，四项都 ≥ 3 分算达标。性能门槛的分母用第 2 周实测的本机带宽与算力，而不是规格表上的峰值。

三类推理岗位的侧重

推理系统岗大致分三类，日常工作和面试侧重都不同。计划以推理框架为主线，同时覆盖算子优化和推理平台的核心内容；投递时按岗位描述调整最后几周的重点。

三类岗位的编码、基础追问和系统设计都要过；具体要求以招聘信息为准。

差异化路线：主线 + 三个放大器

主线是所有候选人都要过的基本盘。在基本盘之上，把系统工程能力放大成辨识度：推理系统里有大量“系统”问题——调度、存储、网络、运行时、可观测性——正是很多偏算法或偏算子的候选人的短板。

逐周计划

按每周约 30 小时设计。每周有主线学习、练习题、算法题、产出和验收清单；验收清单全部打勾再进入下一周。已经熟悉的内容做完章首自测和练习题就跳过，把省下的时间给作品和算法题。

四个里程碑

每个里程碑都是一次“模拟入职考核”：到点检查，没达标就停下来补，不要带着窟窿进下一阶段——面试的追问总会落到窟窿上。

作品与开源贡献

简历上最有说服力的是“做过、测过、被合入”。下面三个作品互相配合：一个证明理解推理引擎全链路，一个体现系统工程的辨识度，一个证明能下到 GPU 底层。开源 PR 让面试官能直接看到你的代码。

参考的课程与教程

对照了国内外公开的 AI 系统课程和教程，取它们各自最强的部分嵌进逐周计划（周计划里标 外部 的链接）。尤其是验证方式：从零实现 + 自带测试、真卡排行榜、带答案的估算习题，都是本计划的验收手段。

本站还没写完的部分（分布式训练、C++ 等）先用这些材料顶上；外部材料以原作者的最新版本为准。

面试准备

面试一般由四部分组成：编码（算法 + 手撕组件）、基础知识追问、系统设计、项目深挖。四部分都要单独练，并且要做模拟面试。

算法题：约 200 道，分周推进

先完成 LeetCode Hot 100，再做下面的专项；每道题限时 25 分钟，做不出看题解后隔 3 天重做。

    手撕组件：面试高频的“现场写”

    每个都要能在 20～40 分钟内写出可运行、边界正确的版本（大部分在练习题里有对应题目）。

      系统设计：10 道必练

      按“需求与规模 → 容量估算 → 架构 → 关键路径（调度 / KV / 通信）→ 故障与扩缩容 → 指标”的结构作答，每道都要给出数字。

        论文与技术报告：精读清单

        精读指能回答“为什么这样设计、代价是什么、数字是多少、如果换成 X 会怎样”。标 ★ 的是面试中最常被追问的工作，必须读到细节。
